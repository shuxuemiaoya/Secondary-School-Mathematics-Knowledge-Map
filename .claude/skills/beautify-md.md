#任务2美化排版

# 通用 Markdown 排版美化规则
> 核心原则：不删除有效内容，不改变原文含义，不破坏公式、图片、表格、链接、标题结构和特殊语法；只做排版整理、结构优化、语言润色与视觉美化。
---
## 1. 总体目标
本规则用于把已有 Markdown 文档整理成结构清楚、层级稳定、排版美观、阅读舒适、便于复习和长期维护的高质量文档。
排版目标包括：
1. 保留原始正文、标题、题目、选项、答案、解析、证明、图片、公式、表格、链接、代码块等有效内容。
2. 统一标题、段落、空行、列表、公式、图片、表格、引用块和 Callout 的排版规范。
3. 清理 PDF / OCR / Word 转换后常见的页码、页眉、占位符、断行、重复题注、错位空格等残留。
4. 将定义、定理、例题、解析、证明、归纳、探究、旁注、提示等内容整理为清晰的视觉模块。
5. 保留必要案例，避免规则过度抽象，确保后续自动化脚本或 AI 排版时不产生歧义。
---
## 2. 处理优先级
排版时按以下优先级执行，后面的美化不得破坏前面的保护规则。
1. **内容完整性优先**：不得丢失正文、公式、图片、表格、题目条件、答案和解析。
2. **结构稳定性优先**：标题层级、目录结构、题目结构不能被随意改写。
3. **语义准确性优先**：可以润色表达，但不得改变数学含义、证明逻辑、概念边界和题目条件。
4. **渲染安全优先**：代码块、公式块、HTML 块、YAML Frontmatter、已有 Callout 等要先保护再处理。
5. **视觉美化最后执行**：Callout、美化图片、多图并排、重点标记等属于最后阶段。
---
## 3. 基本约束
### 3.1 不允许做的事情
- 不删除正文中的有效内容。
- 不改变题目条件、答案、解析、证明过程和公式含义。
- 不破坏已有图片路径、附件链接、网页链接和 Obsidian Wikilink。
- 不把疑似正文的数字误删为页码。
- 不为了美观而改写教材、教辅或题库原有的知识顺序。
- 不把所有内容都强行做成 Callout，避免页面过度卡片化。
### 3.2 允许做的事情
在不改变原意的前提下，可以进行以下处理：
- 调整空行、缩进、段落边界、列表符号。
- 统一中英文、数字、公式之间的空格。
- 修复 OCR 导致的明显断句、重复空格、页眉页码、占位符。
- 将松散内容整理为定义、定理、例题、解析、证明、提示、旁注、归纳等模块。
- 将过大的图片居中缩放，将连续相关图片整理为多图并排。
- 将结构混乱但内容完整的表格整理为 Markdown 表格或稳定 HTML 表格。
- 对报告式、口语化、重复性说明进行适度语言优化，使其更正式、清晰。
### 3.3 模糊情况处理原则
遇到无法确定是否为有效内容的部分，采用保守策略：
| 模糊内容 | 推荐处理 |
| :--- | :--- |
| 单独数字行 | 若上下文像页码则删除；若可能是题号、数据、公式编号则保留 |
| 残缺表格 | 不盲目重写；先判断是否能恢复表头、行列关系和公式含义 |
| 图片连续出现 | 不自动合并所有图片；只有题注、编号、上下文明显相关时才并排 |
| 普通加粗句 | 不默认提升为标题；只有承担结构职责时才改为标题 |
| 公式中的英文 | 不按普通英文混排规则强行加空格，优先服从 LaTeX 语法 |

## 4. 标题层级规则
### 4.1 标题职责
标题只承担结构职责，不应用来做普通强调。
| 标题层级 | 推荐用途 | 示例 |
| :---: | :--- | :--- |
| `#` | 文档标题、一级章节 | `# 第一章 函数` |
| `##` | 主要章节、目录一级条目 | `## 1.1 函数的概念` |
| `###` | 小节、主题模块 | `### 一、函数的定义` |
| `####` | 子模块、局部知识点 | `#### 定义域的求法` |
| `#####` | 练习、探究、阅读、活动、提示等辅助板块 | `##### 探究` |
| `######` | 更细说明，谨慎使用 | `###### 补充说明` |
### 4.2 标题基本格式
- 标题前后保留空行。
- 同级标题风格保持一致。
- 不为了视觉效果随意提升标题层级。
- 不让普通加粗文本伪装成标题。
- 不让标题层级大幅跳跃，例如从 `##` 直接跳到 `#####`，除非原文就是功能性小板块。
- 如果原文存在目录，正文标题应尽量服从目录结构。
### 4.3 标题语言优化
允许在不改变含义的前提下规范标题。
```markdown
优化前：## 第四章  数列
优化后：## 第四章 数列
```
```markdown
优化前：##### 1、知识点总结
优化后：#### 1. 知识点总结
```
```markdown
优化前：### 阅读与思考  斐波那契数列
优化后：### 阅读与思考：斐波那契数列
```
### 4.4 非目录标题处理
若文档已经有明确目录或章节结构，应避免让非目录中的临时标题占用 H1-H3。
推荐规则：
- 目录中的章、节、小节可以使用 H1-H3。
- 非目录中的“思考”“探究”“练习”“例题”“阅读材料”“旁注”等功能性标题，通常使用 H4-H5 或 Callout。
- 不在目录中的重复小标题，如“复习题”“小结”“方法提示”，应根据上下文放到合适层级，不要抢占章标题层级。
---
## 5. 段落、空行与列表规则
### 5.1 段落与空行
- 每个自然段之间保留一个空行。
- 标题、公式块、图片块、表格块前后保留空行。
- H1、H2 前可保留两个空行，形成章节分隔感。
- H3-H5 前保留一个空行即可。
- 同一题目内部不要插入过多空行，避免题干、图片、选项、解析断裂。
- 删除连续三行以上空行，通常压缩为一行。
- 行尾多余空格应删除；若需要 Markdown 软换行，可保留两个尾部空格。
### 5.2 段落整理
过长段落可以按语义拆分；OCR 错误拆断的句子可以合并。
```markdown
优化前：
分析由于已知条件较多所以先寻找角之间的关系然后利用平行线性质求解。
优化后：
分析：由于已知条件较多，先寻找角之间的关系，再利用平行线性质求解。
```
```markdown
优化前：
一般地，在平面内，将一个图形按某一方向移动一定的距离，
这样的图形运动叫作平移（translation）。
优化后：
一般地，在平面内，将一个图形按某一方向移动一定的距离，这样的图形运动叫作平移（translation）。
```
### 5.4 选择题选项
选择题选项可以同行，也可以分行。关键是边界清楚、风格统一。
```markdown
(A) 选项一  (B) 选项二  (C) 选项三  (D) 选项四
```
或：
```markdown
A. 选项一  
B. 选项二  
C. 选项三  
D. 选项四
```
不建议把选项拆成无法识别的散乱段落。

## 6. 中英文、数字、公式与符号间距
### 6.1 盘古间距
中文与英文、数字、行内公式之间建议保留一个半角空格。
```markdown
优化前：如图7.1-1，设a1为首项，公差为d。
优化后：如图 7.1-1，设 $a_1$ 为首项，公差为 $d$。
```
```markdown
优化前：使用Obsidian整理Markdown文件。
优化后：使用 Obsidian 整理 Markdown 文件。
```
```markdown
优化前：在正三棱柱$ABC-A_{1}B_{1}C_{1}$中，E是$BB_{1}$中点，AB=2。
优化后：在正三棱柱 $ABC-A_{1}B_{1}C_{1}$ 中，$E$ 是 $BB_{1}$ 中点，$AB = 2$。
```
### 6.3 不应过度处理的情况
以下情况不要强行加空格或替换：
- 文件路径：`images/xxx/abc.jpg`
- URL：`https://example.com/a-b`
- 代码：`function_name(arg)`
- LaTeX 命令：`\left`、`\infty`、`\frac{a}{b}`
- Obsidian 链接：`[[函数的概念]]`、`![[图片.png]]`

## 7. LaTeX 数学公式规则
> 若文档不包含数学公式，可跳过本节；若文档包含数学、物理、化学等公式，本节优先级很高。
### 7.1 行内公式
行内公式使用单 `$...$` 包裹。
处理规则：
- 去除公式内部首尾多余空格，例如 `$ b $` 改为 `$b$`。
- 公式与中文之间保留适当空格。
- 变量、角标、下标、序列项尽量使用标准 LaTeX。
- 不破坏已经正确闭合的 `$...$`。
- 不把普通货币符号、代码中的 `$` 错当公式边界。
示例：
```markdown
优化前：首项为a1，公差为d
优化后：首项为 $a_1$，公差为 $d$
```
```markdown
优化前：E是BB1中点，AB=2
优化后：$E$ 是 $BB_1$ 中点，$AB = 2$
```
### 7.2 行间公式
较长公式、重要结论、推导过程使用行间公式。
```latex
$$
a_n = a_1 + (n-1)d
$$
```
要求：
- 块公式前后各保留一个空行。
- 不把短小变量强行改成行间公式。
- 多行推导使用 `aligned`、`cases`、`array` 等环境。
- 公式内需要中文解释时，优先放在公式外；必须写入公式时使用 `\text{...}`。
### 7.3 多行公式对齐
复杂推导建议使用 `aligned`。
```latex
$$
\begin{aligned}
S_n &= a_1 + (a_1+d) + (a_1+2d) + \cdots + [a_1+(n-1)d], \\
S_n &= a_n + (a_n-d) + (a_n-2d) + \cdots + [a_n-(n-1)d].
\end{aligned}
$$
```
几何、代数、数列、概率等推导均可采用这种格式。
### 7.4 分段函数
分段函数可使用 `array` 或 `cases`。
```latex
$$
a_n = \left\{
\begin{array}{ll}
S_1, & n = 1, \\
S_n - S_{n-1}, & n \geqslant 2.
\end{array}
\right.
$$
```
### 7.8 编号公式
原书中使用 ①②③④⑤⑥ 等编号的公式，应保留编号体系。
```latex
$$
9, 9^{2}, 9^{3}, \dots, 9^{10};\tag{①}
$$
```
若原文已有公式编号，不要随意改成新的编号体系。

8. Obsidian Callout 结构化规则
	Callout 是增强可读性的工具，不是必须对所有内容使用。只有当内容具有明确功能时，才建议转为 Callout。
8.1 Callout 类型映射
原始内容类型	推荐 Callout	使用说明
例题 / 典型问题	> [!example]	用于完整题目卡片
分析 / 解析 / 解 / 证明	> > [!abstract]-	通常作为例题内部的二级折叠块
定义 / 定理 / 公理 / 核心性质	> [!important]	用于重点知识、核心结论
思考	> [!think]	用于引入性设问
探究	> [!explore]	用于操作、观察、实验、发现规律
归纳 / 方法提示	> [!tip]	用于规律总结、解题技巧
注意 / 易错提醒	> [!warning]	用于限制条件、易错点
旁注 / 背景	> [!info]	用于辅助说明、历史背景
类比说明	> [!note]	用于帮助理解的类比材料
练习	> [!exercise]	用于随堂练习、巩固题
小结 / 总结	> [!summary]	用于章节归纳
可根据 Obsidian 主题自定义 think、explore、exercise 等 Callout 样式。

8.2 例题卡片规则
例题应整理为完整卡片，题干、条件、图片、图注、分析、解答都尽量保留在同一个 example Callout 内。
> [!example] **例题 1**
> 在正三棱柱 $ABC-A_1B_1C_1$ 中，$E$ 是 $BB_1$ 的中点，求相关角或距离。
>
> <div align="center">
>   <img src="images/.../example.jpg" width="55%" />
> </div>
>
> > [!abstract]- 分析
> > 先根据空间关系确定投影，再利用三角函数建立关系。
>
> > [!abstract]- 解
> > 根据题意可得……
> >
> > $$
> > \cos \theta = \frac{b}{a}
> > $$
例题内部的“分析”“解”“证明”“解析”建议统一使用二级折叠 Callout：
> > [!abstract]- 分析
> > 分析内容……
> > [!abstract]- 证明
> > 证明过程……
关键要求：
	• 二级 Callout 内每一行都必须带 > > 前缀。
	• 图片、公式、HTML 标签、空行也必须带正确前缀。
	• 不允许中途漏掉 >，否则 Obsidian 会把后续内容渲染到卡片外。
错误示例：
> [!example] **例题**
> 题目内容
>
> > [!abstract]- 解
> > 第一步
$$
a_n = a_1 + (n-1)d
$$
上面的公式会泄漏到 Callout 外。
正确示例：
> [!example] **例题**
> 题目内容
>
> > [!abstract]- 解
> > 第一步
> >
> > $$
> > a_n = a_1 + (n-1)d
> > $$

8.4 Callout 使用边界
不要把以下内容强行转成 Callout：
	• 普通连续正文。
	• 已经结构清楚的列表。
	• 过短且不承担功能的句子。
	• 大段没有明确板块属性的材料。
	• 会导致嵌套过深、阅读困难的连续内容。
Callout 的原则是：美化结构，而不是制造结构。
## 9. 图片与多媒体排版规则
### 9.1 图片路径保护
原始图片路径必须完整保留。
```markdown
![](images/.../xxx.jpg)
```
不要随意改变：
- 文件名。
- 文件夹名。
- 中文路径。
- URL 编码。
- Obsidian 附件链接。
### 9.2 单图居中
单张图片可使用 HTML 居中并控制宽度。
```markdown
<div align="center">
  <img src="images/.../xxx.jpg" alt="图示" width="60%" />
</div>
```
### 9.3 图片题注
题注应紧跟图片，保持视觉关联。
```markdown
![](images/.../xxx.jpg)  
图 7.1-1
```
常见题注形式：
- `图 7.1-1`
- `图 7.2-3`
- `(1)`、`(2)`、`(3)`
- `(第 1 题)`
- `甲`、`乙`、`丙`、`丁`
- `①`、`②`、`③`、`④`
### 9.4 多图并排
连续相关图片可并排展示，避免页面过长。
| 图片数量 | 推荐宽度 |
| :---: | :---: |
| 双图并排 | `45%` |
| 三图并排 | `30%` |
| 四图并排 | `22%` |
示例：
```markdown
<div align="center">
  <img src="images/1.jpg" width="45%" style="display:inline-block; margin-right:8px;" />
  <img src="images/2.jpg" width="45%" style="display:inline-block;" />
  <br>
  <span>（1）</span>&emsp;&emsp;<span>（2）</span>
</div>
```
### 9.5 多图分组识别
适合并排的情况：
- 同一道题的多个子图。
- 同一图形变化过程，如平移、旋转、折叠、投影。
- 同一概念的对比图。
- 连续编号图片，如 `①②③④`。
- 科赫雪花曲线等迭代图。
不适合并排的情况：
- 图片来自不同题目。
- 图片之间没有共同题注或上下文关系。
- 图片尺寸差异过大，并排后难以阅读。
- 图片中包含大量文字，并排后文字过小。
### 9.6 图片与 Callout 嵌套
如果图片属于例题、解析、证明或提示卡片，图片也必须放在 Callout 内。
```markdown
> [!example] **例题**
> 题目内容……
>
> <div align="center">
>   <img src="images/.../xxx.jpg" width="55%" />
> </div>
```
二级 Callout 内同理需要 `> >` 前缀。

## 10. 表格排版规则
### 10.1 普通数据表
结构清晰的数据表优先转换为 Markdown 表格。
要求：
- 表头清楚。
- 行列数量一致。
- 变量使用行内公式，例如 `$n$`、`$a_n$`。
- 单元格中的公式完整闭合。
- 不删除原有数据。
```markdown
| $n$ | 1 | 2 | 3 | 4 |
| :---: | :---: | :---: | :---: | :---: |
| $a_n$ | 2 | 4 | 8 | 16 |
```
### 10.2 对照表
概念、公式、性质的对照适合整理为表格。
```markdown
| 名称 | 等差数列 $\{a_n\}$ | 等比数列 $\{b_n\}$ |
| :--- | :--- | :--- |
| **定义** | $a_{n+1} - a_n = d$（常数） | $\frac{b_{n+1}}{b_n} = q$（常数，$b_n \neq 0, q \neq 0$） |
| **通项公式** | $a_n = a_1 + (n-1)d$ | $b_n = b_1q^{n-1}$ |
| **常用性质** | 若 $m+n=p+q$，则 $a_m+a_n=a_p+a_q$ | 若 $m+n=p+q$，则 $b_m b_n=b_p b_q$ |
```
### 10.3 HTML 表格
复杂表格可以保留 HTML `<table>`，尤其是：
- 合并单元格较多。
- 表内有图片。
- 表内有多行公式。
- Markdown 表格无法稳定渲染。
保留 HTML 表格时要求：
- 标签闭合完整。
- 行列顺序正确。
- 不出现明显 OCR 乱码。
- 不破坏 Obsidian 或目标阅读器渲染。
### 10.4 严重损坏表格重构
若 OCR 导致表格严重错位，但内容可识别，可以重构。
重构原则：
1. 不新增原文没有的数学结论，除非可以从上下文明确恢复。
2. 不删除任何可识别数据。
3. 表头、行名、列名必须清晰。
4. 对公式使用 LaTeX 统一排版。
5. 对不确定内容保留原文或标注为待核查，不凭空补写。
---
## 11. OCR / PDF / Word 转换残留清理
### 11.1 常见残留类型
需要识别并处理：
- 单独成行的页码，如 `6`、`22`、`1016`。
- 页眉页脚，如 `6 第四章 数列`、`22 第四章 数列`、`数 学`。
- 无意义分隔符，如 `##### ● ●`。
- 重复标题或重复题注。
- 图片与题注分离。
- 公式被错误断行。
- 表格被拆散为多段文本。
- 中文之间异常空格，例如 `数 学`。
- 英文、数字、公式与中文粘连。
### 11.2 清理原则
- 明显无意义的页码、页眉、页脚可以删除。
- 疑似正文内容的数字、编号、公式编号不能误删。
- 分隔符后面的有效内容必须保留，并转化为合适结构。
- 重复题注只在确认重复且无新信息时清理。
- 清理前后检查标题、图片、公式、表格数量是否异常变化。
### 11.4 页码误删防护
可以删除的情况：
```text
6
22
1016
```
但以下情况应保留：
```text
例 6
第 22 题
S_6 = a_1 + a_2 + \cdots + a_6
图 7.2-6
```
判断页码时应结合上下文，而不是只看是否为数字。

## 12. 推理、证明与解题过程排版
### 12.1 推理链格式
证明、推理、解题链条应保持逐步清晰。
```markdown
∵ $b \perp a$（已知），
∴ $\angle 1 = 90^{\circ}$（垂直定义）。
∵ $c \perp a$（已知），
∴ $\angle 2 = 90^{\circ}$（垂直定义）。
∴ $\angle 1 = \angle 2$。
∴ $b \parallel c$（同位角相等，两直线平行）。
```
### 12.2 分析、解、证明、结论的边界
推荐结构：
```markdown
> [!example] **例 4**
> 如图，已知 $\angle 1 = \angle 2$，求 $\angle ABC$。
>
> > [!abstract]- 分析
> > 由于已知角之间存在相等关系，可先推出两直线平行，再利用平行线性质求角。
>
> > [!abstract]- 解
> > ∵ $\angle 1 = \angle 2$，
> >
> > ∴ $a \parallel b$（内错角相等，两直线平行）。
> >
> > ∴ $\angle 3 = \angle ABC$（两直线平行，同位角相等）。
```
### 12.3 不要破坏原有逻辑
- 不把证明步骤改成只剩结论。
- 不删除“因为”“所以”之间的中间理由。
- 不随意补充教材中没有的证明。
- 不把原文的“分析”和“解”混为一段。

## 16. 最终效果标准
整理后的 Markdown 文件应达到以下效果：
1. 章节结构清楚，标题层级稳定。
2. 段落、列表、公式、图片、表格之间有清晰边界。
3. 行内公式和行间公式能正确渲染，数学符号规范。
4. 图片不再无序堆叠，图号、题注、子图关系清楚。
5. 例题、解析、证明形成完整卡片，方便自测与折叠阅读。
6. 定义、定理、归纳、探究、旁注各有明确视觉样式。
7. OCR / PDF 转换残留被清理或重构，不影响阅读。
8. 表格可读性明显提升，复杂对照内容结构稳定。
9. 文档既保留原始内容，又适合长期维护、复习、导出和二次加工。
---
## 17. 一句话原则
**先保护内容，再修复结构，最后美化视觉；宁可保守保留，也不要误删误改。**
